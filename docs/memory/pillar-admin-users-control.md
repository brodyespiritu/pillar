**Add user** (Admin → Users → "Add user"): `src/pages/admin/AddUserModal.jsx` (+`addUser.css`) — a 5-step slide-up card (Account → Access → Profile → Security → Review). Creates BOTH the Supabase Auth login and the `staff` row (keyed by the auth id) via edge function **`admin-create-user`** (service role; verifies the caller is an admin via their JWT; rolls back the auth user if the staff insert fails). `src/lib/admin.js` → `createUser()` invokes it. Permissions model in admin.js: `MODULES` (cares/guests/calendar/members/email/sms/attendance/admin) × `ACCESS` none|view|edit, stored in new `staff.permissions` jsonb; `permsForRole()` gives role presets. Added staff columns `title`, `phone`, `permissions` (see `admin-schema.sql`). **Setup:** run updated `admin-schema.sql` + `supabase functions deploy admin-create-user`. NOTE: permissions are stored but not yet enforced by route guards (follow-up).

**Control** (Admin → user row ⋯ → "Control"): consent-based live co-session, NOT OS remote control. `src/context/ControlContext.jsx` (+`control.css`), `ControlProvider` wraps routes in `App.jsx`. Uses **Supabase Realtime broadcast** on channel `ctrl:<userId>` (no DB/schema). Flow: admin `requestControl(id,name)` → target sees "Give control to [admin]?" popup → accept → admin's **cursor position (throttled 40ms), clicks (ripples), and route navigation** broadcast to the target, who renders a labeled ghost cursor + follows navigation; both sides get a banner with End. Coordinates are viewport fractions so they map across screen sizes. Every logged-in user is auto-subscribed to their own `ctrl:` channel to receive requests. **Remote click execution IS enabled:** on admin click, `cssPath()` builds a body>tag:nth-of-type chain to the clicked element and broadcasts it (+ viewport-fraction coords + scroll). Target runs `execRemoteClick()` → `document.querySelector(path)` (fallback `elementFromPoint`) → `el.focus()`+`el.click()` (skips any `.ctl-*` control UI). Path targeting keeps clicks landing on the same logical element across different screen sizes; window-scroll is mirrored too (note: most Pillar pages scroll inner containers, not window, so scroll sync is best-effort — path is the reliable part). CAVEAT: the admin's click also executes on the admin's OWN screen, so a server mutation runs in BOTH sessions (double-execute) — fine for navigation/UI, risky for destructive/duplicating actions. Not built: remote typing/keyboard. Realtime still untested here (single session) — verify with two browsers.
